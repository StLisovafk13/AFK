# VSCO Archive на GitHub Pages

Галерея, профили, комментарии и карта архива VSCO, опубликованные GitHub Actions на домене **github.io**. Отдельный сервер и аккаунт другого хостинга не нужны. База остаётся в Neon, бот продолжает работать с ней как раньше.

GitHub Pages обслуживает статические файлы. Поэтому сайт показывает **снимок базы**, который Actions обновляет каждые 6 часов (00:17, 06:17, 12:17, 18:17 UTC), при изменении сайта в `main` или по ручному запуску. Расписание GitHub может задерживаться. Новые записи бота доступны на сайте после успешного workflow, без прямого подключения браузера к Neon.

## Первый запуск

1. Слейте PR в `main`.
2. Откройте **StLisovafk13/AFK → Settings → Pages → Build and deployment → Source → GitHub Actions**. При первом merge workflow может завершиться ошибкой, пока Pages ещё не включён; после настройки запустите его вручную.
3. В **Settings → Secrets and variables → Actions → Repository secrets** добавьте:

   | Secret | Значение |
   | --- | --- |
   | `DATABASE_URL` | Строка подключения Neon Connect к уже импортированной базе. Если секрет уже есть, используйте его |
   | `ARCHIVE_PASSWORD` | Уникальный случайный пароль длиной 20–1024 символа для открытия архива |

   GitHub Secrets не переносятся из настроек Sites автоматически. Для экспорта достаточно роли Neon с `CONNECT`, `USAGE` на схему и `SELECT` на `items`, `links`, `comments`. Значения секретов не добавляйте в репозиторий, workflow или `VITE_*`.
4. Откройте **Actions → Online archive website → Run workflow → main**.
5. Дождитесь успешных этапов **Test and build archive**, **Build encrypted Pages archive**, **Publish to github.io**. Откройте адрес из результата deploy. Для текущего репозитория стандартный адрес — **https://stlisovafk13.github.io/AFK/**.
6. Введите `ARCHIVE_PASSWORD`. Логин не нужен. Вводимый пароль используется только в браузере для расшифровки и не отправляется на сервер. По кнопке «Выйти» или после перезагрузки страницы пароль нужно ввести снова.

Workflow читает production-секреты только на этапе экспорта из `main`; проверки PR работают на тестовых данных. Публикация использует официальный Pages artifact и OIDC, отдельный PAT не нужен.

## Как хранятся данные

```text
Бот → Neon → GitHub Actions: SELECT → gzip + AES-256-GCM → GitHub Pages
                                                              ↓
                                         пароль → расшифровка в браузере
```

HTML, JS и зашифрованные файлы сайта доступны публично, как у обычного GitHub Pages. Имена профилей, чаты, ссылки, координаты, комментарии и индекс архива находятся **внутри шифрования**. Открытый manifest содержит только версию формата, случайный идентификатор, salt и параметры ключа.

Ключ получается из пароля через PBKDF2-SHA-256 (600 000 итераций, случайный salt), шифрование — AES-256-GCM с отдельным случайным IV для каждой части. Сначала данные сжимаются gzip. Неверный пароль и повреждённые файлы не проходят проверку аутентичности. Сайт не сохраняет пароль в localStorage/sessionStorage; он остаётся в памяти открытой вкладки.

Любой может скачать зашифрованные файлы и пытаться подобрать пароль вне сайта, поэтому нужен длинный случайный пароль. Все, кто знает пароль, видят весь снимок; фильтр чата не является разграничением доступа. Смена пароля и новая публикация защищают новый снимок, но не отзывают ранее скачанные версии.

Снимок не коммитится в Git. Runner записывает в публикуемый каталог только зашифрованные части; значения пароля и `DATABASE_URL` не попадают в frontend, manifest или логи экспорта. При ошибке экспорта публикация не запускается, предыдущая версия сайта остаётся доступной.

## Объём и просмотр

Экспорт читает базу пакетами по 1 000 строк с курсором по числовому ID и верхней границей на начало экспорта. Это исключает позднее добавленные записи. Изменения и удаления уже существующих строк во время экспорта могут отразиться частично; длинная транзакция и блокировка работы бота не используются.

В снимок входят необходимые поля медиа, профилей, координаты, источник и до 200 комментариев записи. Большой `meta_json`, сведения о камере, локальные пути и `added_by` не экспортируются. Изображения остаются по исходным URL VSCO и не копируются на Pages. Недоступность VSCO/VPN посетителя может влиять на превью.

При входе загружается компактный зашифрованный каталог. Галерея читает части по 256 записей и показывает по 48 за страницу; профили — по 36; карта — до 2 000 последних подходящих точек. Отдельные части с координатами ускоряют карту. В браузере кэшируется до 16 частей. Полная база не загружается при открытии страницы.

Дата снимка отображается под галереей. «Обновить» проверяет последнюю публикацию Pages. Данные в Neon эта кнопка не запрашивает. Если во время просмотра сменился пароль, выполните выход и войдите с новым паролем.

Экспорт ограничен 500 МиБ зашифрованных данных, чтобы сохранять запас относительно ограничений Pages. Сжатый снимок без `meta_json` должен быть значительно меньше исходной SQLite, но фактический размер зависит от данных. GitHub может отключать scheduled workflows в публичных репозиториях без активности; доступен ручной запуск.

## Локальная проверка

Node.js 22.13+:

```sh
cd web
npm ci
npm run check
npm test
npm run build
```

Для локального экспорта задайте `DATABASE_URL` и `ARCHIVE_PASSWORD` как переменные окружения shell. Либо скопируйте `.env.example` в игнорируемый `.env` и выполните:

```sh
node --env-file=.env --import tsx scripts/export-pages.ts
npm run preview
```

Для проверки project URL используйте `PAGES_BASE_PATH=/AFK npm run build`, затем экспорт и `npm run preview`; откройте `/AFK/`. На Windows PowerShell задайте `$env:PAGES_BASE_PATH='/AFK'` перед сборкой. При разработке UI `npm run dev` использует тот же базовый путь; просмотр данных требует подготовленного снимка, поэтому для проверки архива используйте `preview`.

Источники: [GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages), [официальный Actions workflow для Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).
